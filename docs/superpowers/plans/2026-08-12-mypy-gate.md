# mypy Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add static type checking to the gate, closing the one category of static analysis this repo has no coverage for.

**Architecture:** mypy as a pinned manual-stage pre-commit hook over `src/memoria_vault`, with its stub dependencies declared in the hook environment so the gate stays offline. The tree is 99% annotated (1,891 of 1,910 defs carry both parameter and return types), so the expensive half of adoption is already done and the baseline can start strict-ish rather than staged. A second pin in `requirements-dev.txt` serves the VS Code extension, held equal to the hook rev by the same assertion pattern that already guards ruff.

**Tech Stack:** mypy (via `pre-commit/mirrors-mypy`), pytest, pre-commit, VS Code `ms-python.mypy-type-checker`.

## Global Constraints

- Correctness command is `python scripts/verify`. It is the one gate.
- Stage explicit paths in `git add`. Never `git add -A`, `--all`, `-u`, or `.`.
- **The gate is offline.** Hook environments are built once and cached; nothing may fetch at run time.
- **One pin per tool**, or two held equal by a test. mypy will have two — the hook rev and `requirements-dev.txt` — for the same reason ruff does: `importStrategy` is `fromEnvironment`, so the editor uses the pip-installed copy and silently falls back to a bundled one if absent.
- mypy is a **checking** tool, not a rewriting one, so it belongs in the manual stage only — never the commit stage. The commit stage is reserved for tools that rewrite files (`ruff-format`, `oxfmt`).
- Type annotations are not a docstring policy. `ANN` and `D` stay disabled in ruff; this plan does not reopen them.
- Every task verifies current state with a command and its expected result before changing anything.

### Task 1: Measure before committing to a strictness level

**Files:**
- None. This task changes nothing.

**Interfaces:**
- Consumes: nothing.
- Produces: the error count that decides Task 2's config. Record it in the commit message of Task 2.

Choosing a strictness level before measuring is how a type-checker adoption turns into a 400-error slog that gets abandoned. This task exists so Task 2's config is derived from evidence.

- [ ] **Step 1: Confirm no type checker exists today**

Run:

```bash
grep -rn "mypy\|pyright\|basedpyright" pyproject.toml requirements-dev.txt .pre-commit-config.yaml .github/workflows/ || echo "no type checker configured - as expected"
git check-ignore -v .mypy_cache && echo "(cache is gitignored, so someone runs mypy by hand with no gate)"
```

Expected: `no type checker configured - as expected`, then a `.gitignore` line matching `.mypy_cache/`.

- [ ] **Step 2: Confirm the annotation density that justifies a strict baseline**

Run:

```bash
python3 - <<'PY'
import ast, pathlib
total = fully = 0
for path in pathlib.Path("src/memoria_vault").rglob("*.py"):
    try:
        tree = ast.parse(path.read_text(encoding="utf-8"))
    except SyntaxError:
        continue
    for node in ast.walk(tree):
        if not isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef)):
            continue
        total += 1
        args = [
            a
            for a in node.args.args + node.args.posonlyargs + node.args.kwonlyargs
            if a.arg not in ("self", "cls")
        ]
        if node.args.vararg:
            args.append(node.args.vararg)
        if node.args.kwarg:
            args.append(node.args.kwarg)
        if node.returns is not None and all(a.annotation is not None for a in args):
            fully += 1
print(f"defs={total} fully-annotated={fully} ({fully / total:.0%})")
PY
```

Expected: roughly `defs=1910 fully-annotated=1891 (99%)`. If density has dropped below about 90%, stop and reconsider the baseline in Task 2 — `disallow_untyped_defs` would then be a large refactor rather than a no-op.

- [ ] **Step 3: Measure the error count at the proposed baseline**

Run:

```bash
python3 -m pip install --quiet --dry-run mypy 2>/dev/null || true
python3 -m venv /tmp/mypy_probe
/tmp/mypy_probe/bin/pip install --quiet mypy types-PyYAML "pydantic-ai-slim[openai]>=2.0"
/tmp/mypy_probe/bin/mypy \
  --python-version 3.12 \
  --check-untyped-defs \
  --warn-redundant-casts \
  --warn-unused-ignores \
  --no-implicit-optional \
  --strict-equality \
  --ignore-missing-imports \
  src/memoria_vault 2>&1 | tail -20
```

Expected: a summary line such as `Found N errors in M files`. **Record N.** This number decides Task 2:

- **N under about 50** — adopt the baseline as written in Task 2 and fix them all in this plan.
- **N between 50 and 300** — adopt the baseline but drop `--check-untyped-defs` and `--strict-equality` for the first landing, then re-add each in its own follow-up commit.
- **N above 300** — do not land a gate that requires 300 fixes. Adopt `--ignore-missing-imports` plus `--warn-redundant-casts` only, land green, and file an issue per additional flag.

- [ ] **Step 4: Identify which errors are missing stubs rather than real defects**

### Task 2: Add the hook and the configuration

**Files:**
- Modify: `pyproject.toml` (new `[tool.mypy]` section)
- Modify: `.pre-commit-config.yaml` (new hook)
- Modify: whichever files under `src/memoria_vault` mypy reports

**Interfaces:**
- Consumes: the error count from Task 1 Step 3 and the stub-less module list from Step 4.
- Produces: a `mypy` hook with id `mypy`, which Task 3's test reads by that id.

- [ ] **Step 1: Add the mypy configuration**

In `pyproject.toml`, add after the `[tool.ruff.lint.per-file-ignores]` block:

```toml
[tool.mypy]
# Scope is src/ only. Tests reach into internals on purpose (SLF001 is
# per-file-ignored there for the same reason) and scripts/ is glue; neither
# earns the annotation burden today. Widening scope is a later decision with
# its own measurement.
files = ["src/memoria_vault"]
python_version = "3.12"

# The tree was 99% fully annotated when this landed (1,891 of 1,910 defs), so
# the expensive half of adoption was already paid. These flags are what that
# density buys: they are near-no-ops here and would be a refactor elsewhere.
check_untyped_defs = true
warn_redundant_casts = true
warn_unused_ignores = true
warn_unused_configs = true
no_implicit_optional = true
strict_equality = true

# Deliberately NOT set: disallow_any_explicit and disallow_any_generics, which
# fight pydantic-ai's generic signatures; and disallow_untyped_defs, which would
# turn the 19 remaining unannotated defs into a blocker for no benefit — the
# density is already 99% and check_untyped_defs covers their bodies.

[[tool.mypy.overrides]]
# Optional extras with no published stubs. Untyped, not defective — the runtime
# guards their absence already (see the `mcp` and `vector` extras in
# [project.optional-dependencies]).
module = ["sqlite_vec.*", "mcp.*"]
ignore_missing_imports = true
```

If Task 1 Step 4 named modules other than these two, add them to the `module` list. If it named none, delete the `[[tool.mypy.overrides]]` block entirely — `warn_unused_configs = true` will otherwise flag it.

If Task 1 Step 3 returned N above 50, remove `check_untyped_defs` and `strict_equality` from this block per that step's guidance, and note in the commit message which flags were deferred.

- [ ] **Step 2: Add the hook**

In `.pre-commit-config.yaml`, add after the ruff repo block:

```yaml
  # mypy is a checking tool, not a rewriting one, so it carries the manual stage
  # only — the commit stage is for hooks that modify files (see the note at the
  # top of this file).
  #
  # `additional_dependencies` is what keeps the gate offline and meaningful:
  # without the stubs and the runtime package, every third-party import resolves
  # to `Any` and the hook is green on a codebase it never actually checked. It
  # is also the one pin Dependabot's pre-commit ecosystem does not move — it
  # bumps `rev` only — the same gap the cspell and markdownlint hooks already
  # carry.
  #
  # Both entries are pinned to an exact version, never a range. A range here
  # resolves at env-build time, so two machines building the environment a month
  # apart type-check against different pydantic-ai signatures and disagree about
  # what is an error. The pin is a snapshot of the runtime dependency, not a
  # second declaration of it: when pyproject.toml's `pydantic-ai-slim` floor
  # moves, move this to match in the same PR.
  #
  # `pass_filenames: false` because [tool.mypy] `files` owns the scope: mypy
  # needs the whole package to resolve cross-module types, and feeding it one
  # changed file at a time reports errors that do not reproduce on a full run.
  - repo: https://github.com/pre-commit/mirrors-mypy
    rev: v1.18.2
    hooks:
      - id: mypy
        pass_filenames: false
        additional_dependencies:
          - types-PyYAML==6.0.12.20250915
          - pydantic-ai-slim[openai]==2.0.0
        stages: [manual]
```

Replace `2.0.0` with the exact `pydantic-ai-slim` version currently resolved in your environment — get it with `python3 -m pip show pydantic-ai-slim | grep ^Version`. Do not leave the `>=2.0` range from `pyproject.toml` here; that file declares a compatibility floor for installers, while this one must name a single version so the gate's verdict is reproducible.

Check the current `mirrors-mypy` release before using `v1.18.2` — run `git ls-remote --tags --sort=-v:refname https://github.com/pre-commit/mirrors-mypy | head -3` and use the newest stable tag. The rev must be a release tag; `tests/test_node_tooling.py` asserts that for every hook repo.

- [ ] **Step 3: Register the hook repo in the pinned-repos assertion**

`tests/test_node_tooling.py::test_precommit_hooks_use_pinned_tool_environments` asserts the exact set of hook repo URLs. Adding a repo without updating it fails that test. Add one line to the set:

```python
        "https://github.com/pre-commit/mirrors-mypy",
```

- [ ] **Step 4: Build the hook environment and verify it is offline**

Run:

```bash
pre-commit install-hooks
pre-commit run mypy --hook-stage manual --all-files
```

Expected: the first command downloads and caches; the second runs with no network. To prove the offline property, re-run the second command with networking disabled if your environment allows it — the hook must still pass. A hook that needs the network at run time violates the gate's offline constraint and must not land.

- [ ] **Step 5: Fix what mypy reports**

Read every error. Fix the code, not the checker:

- A genuine `None` leak — add the guard the type says is missing.
- A real signature mismatch — correct the annotation or the call.
- A third-party module with no stubs — add it to `[[tool.mypy.overrides]]`, not a `# type: ignore`.
- A site where mypy is genuinely wrong — use a **specific** code: `# type: ignore[arg-type]` with a comment giving the reason. A bare `# type: ignore` is rejected by ruff's `PGH` family if the ruff-rule-expansion plan has landed, and should be rejected by review regardless.

- [ ] **Step 6: Verify clean**

Run:

```bash
pre-commit run mypy --hook-stage manual --all-files
```

Expected: PASS.

- [ ] **Step 7: Run the full gate**

Run:

```bash
python scripts/verify
```

Expected: `verify: OK`. mypy runs as part of the first roster entry (`pre-commit run --hook-stage manual --all-files`), so no change to `scripts/verify` is needed — the roster already delegates the whole lint stage to pre-commit.

- [ ] **Step 8: Commit**

```bash
git add pyproject.toml .pre-commit-config.yaml tests/test_node_tooling.py src/memoria_vault
git commit -m "feat: add mypy to the lint gate

src/memoria_vault only, at a strict-ish baseline the 99% annotation density
already supports. Stubs pinned in the hook environment so the gate stays
offline; without them every third-party import is Any and the hook is green
on nothing."
```

- [ ] **Step 1: Read the pattern this follows**


Expected: the comment and assertion block holding `requirements-dev.txt`'s ruff pin equal to the ruff hook rev, because `ruff.importStrategy` is `fromEnvironment`. mypy's extension has the identical setting and therefore the identical failure mode.

- [ ] **Step 2: Pin mypy for the editor**

In `requirements-dev.txt`, add below the ruff block:

```
# The second tool pinned twice, for the same reason as ruff above: the mypy VS
# Code extension's `mypy-type-checker.importStrategy` is `fromEnvironment`, so
# the editor type-checks with this mypy and falls back to its own bundled copy
# — pinned by no gate — when the line is absent. It must equal the
# mirrors-mypy rev in .pre-commit-config.yaml; the assertion in
# tests/test_node_tooling.py fails when it does not.
mypy==1.18.2
```

Use the exact version matching the hook rev chosen in Task 2, without the leading `v`.

- [ ] **Step 3: Write the equality assertion**

In `tests/test_node_tooling.py`, inside `test_precommit_hooks_use_pinned_tool_environments`, add after the ruff assertion block:

```python
    # mypy is the second tool pinned twice, and for the same reason as ruff:
    # `mypy-type-checker.importStrategy` is `fromEnvironment`, so a skewed
    # editor copy reports type errors the gate does not, and misses ones it does.
    mypy_pins = _pins("mypy")
    assert len(mypy_pins) == 1, f"expected exactly one mypy pin, got {mypy_pins}"
    mypy_version = mypy_pins[0].strip().removeprefix("mypy==")
    mypy_rev = pinned_repos["https://github.com/pre-commit/mirrors-mypy"]
    assert mypy_rev.removeprefix("v") == mypy_version, (
        f"mypy is {mypy_version} in requirements-dev.txt but {mypy_rev} in the "
        "pre-commit hook; the editor and the gate would disagree"
    )
```

- [ ] **Step 4: Verify the assertion holds, and that it can fail**

Run:

```bash
python3 -m pytest tests/test_node_tooling.py -q
sed -i 's/^mypy==.*/mypy==1.0.0/' requirements-dev.txt
python3 -m pytest tests/test_node_tooling.py -q
git checkout requirements-dev.txt
python3 -m pytest tests/test_node_tooling.py -q
```

Expected: PASS, then FAIL with "the editor and the gate would disagree", then PASS. The middle step is the proof the assertion is live.

Note: `git checkout requirements-dev.txt` discards the deliberate corruption **and** the Step 2 edit if it was not committed. Re-apply Step 2 if so, or run Step 2 and Step 3 as one commit before this verification.

- [ ] **Step 5: Commit**

```bash
git add requirements-dev.txt tests/test_node_tooling.py
git commit -m "test: hold the editor mypy equal to the gate mypy

Same pattern and same reason as ruff: importStrategy is fromEnvironment, so a
skewed editor copy reports type errors the gate does not."
```

### Task 4: Configure VS Code to match

**Files:**
- Modify: `.vscode/settings.json`
- Modify: `.vscode/extensions.json`

**Interfaces:**
- Consumes: the `requirements-dev.txt` pin from Task 3.
- Produces: nothing.

Two editor-side changes matter. The extension must read the pinned mypy, and Pylance must stop running a *second*, unpinned type checker beside it — `ms-python.python` pulls Pylance, whose default `typeCheckingMode` is `basic`, so today the editor already type-checks with a pyright build nothing pins. Leaving both on means two checkers disagreeing in the same buffer, and contributors learning to ignore both.

- [ ] **Step 1: Verify what the editor checks today**

Run:

```bash
grep -n "python.analysis\|typeCheckingMode\|mypy" .vscode/settings.json || echo "no analysis settings - Pylance is at its default"
grep -n "ms-python.python" .vscode/extensions.json
```

Expected: `no analysis settings - Pylance is at its default`, and `ms-python.python` present in the recommendations. That is the unpinned second checker.

- [ ] **Step 2: Point the mypy extension at the pinned copy and silence Pylance's checker**

In `.vscode/settings.json`, add:

```json
  "mypy-type-checker.importStrategy": "fromEnvironment",
  "python.analysis.typeCheckingMode": "off",
```

`fromEnvironment` mirrors the existing `ruff.importStrategy` line and is what makes Task 3's pin the version the editor actually uses. `typeCheckingMode: off` leaves Pylance doing completion, navigation, and hover — everything it is good at — while the single pinned mypy owns type verdicts. This is a settings default, not a lock: anyone who wants Pylance's checker back flips it in their user settings.

- [ ] **Step 3: Recommend the extension**

In `.vscode/extensions.json`, add to `recommendations`, next to `charliermarsh.ruff`:

```json
    "ms-python.mypy-type-checker",
```

- [ ] **Step 4: Verify both files parse and the guard test still passes**

Run:

```bash
python3 -c "
import json, re
for f in ('.vscode/settings.json', '.vscode/extensions.json'):

print(json.loads(re.sub(r'^\s*//.*$', '', open('.vscode/settings.json').read(), flags=re.M))['mypy-type-checker.importStrategy'])

python3 -m pytest tests/test_node_tooling.py -q
```

Expected: `fromEnvironment`, then PASS. `test_oxc_editor_tools_match_the_pinned_hook_versions` asserts `oxc.oxc-vscode` is still in `extensions.json` — editing the wrong line breaks it, which is the guard working.

- [ ] **Step 5: Commit**

```bash

Pylance's own checker goes off: it was a second, unpinned type checker running
```

## Self-Review

**Spec coverage.** Measurement before commitment (Task 1), hook plus config plus fixes (Task 2), the two-pin equality assertion (Task 3), editor parity including turning off the redundant checker (Task 4). The decision to use mypy rather than pyright is settled in the session and restated in the Architecture line — it follows from the offline constraint, the one-pin rule, and the existing root-`package.json` guard, not from preference.

**Placeholder scan.** No TBDs. Task 1 Step 3 produces a number that Task 2 consumes, with all three branches spelled out rather than deferred. Task 2 Step 2 says to check the current `mirrors-mypy` tag rather than trusting `v1.18.2` — that is a verification step, not a placeholder.

**Type consistency.** The hook id is `mypy` in Task 2 and read as `mypy` in Task 3. The repo URL is `https://github.com/pre-commit/mirrors-mypy` in Task 2 Step 3 and Task 3 Step 3. The helper `_pins()` already exists in `tests/test_node_tooling.py` with the signature Task 3 uses.

**Ordering.** Tasks 2, 3, and 4 are strictly sequential — Task 3 reads the rev Task 2 sets, Task 4 relies on the pin Task 3 creates. Task 1 changes nothing and can be re-run at any point.

**Risk worth naming.** Task 2's `additional_dependencies` is a pin Dependabot does not move: its pre-commit ecosystem bumps `rev` only. The repo already carries this gap for `cspell@10.0.1` and `markdownlint-cli@0.49.1`, so this is consistent rather than new — but it means the stub versions age silently, and `warn_unused_ignores` is what will eventually make that visible.
